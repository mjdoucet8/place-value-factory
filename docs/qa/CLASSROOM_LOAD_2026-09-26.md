## Sustained history workload

`npm run test:sustained` creates another private disposable PostgreSQL cluster. Ninety fictional learners in three classes first earn a five-order Level 1 path and five-order practice attempt through the real API. For each learner the test then copies ten previously validated five-order attempts into older timestamps as **synthetic performance history**; these copied records are ineligible for mastery and do not substitute for the earned progression suite. The timed start has 1,080 attempts, 5,400 responses and evidence rows, and a roughly 25.5 MB database. It runs for at least 90 seconds in 30-learner waves: each learner reads a profile, starts and ships five replay orders and retries the first immutable answer; three full-year class report reads overlap each round. The test asserts final attempt/answer/receipt counts, identical retries, class-local teacher rosters/totals and unchanged two-star rewards. Timing includes the HTTP request and parsed JSON response. A 50 ms sampler records PostgreSQL advisory waits and process RSS.

The predeclared 500 ms p95 threshold applies separately to profile, start, answer, retry and report. The final retained three-process run completed 29 rounds in 94.8 seconds at 221 requests/s with zero request errors and zero observed advisory-lock waits. Its p95 profile/start/answer/retry/report latencies were **195/486/205/210/1,042 ms**. The test verified 3,690 attempts, 18,450 answers, 16,740 command receipts, class-local report totals and unchanged two-star rewards. The database grew from about 25.5 MB to 90 MB; combined load-client and three API-worker RSS peaked at 1.35 GB (PostgreSQL memory excluded). Duplicate answer retries were deliberately sent to a different API worker. **The full-year report p95 fails the target**, so PERF-01 and the overall local pilot-readiness milestone remain open. The shorter fresh-database test above cannot stand in for this history workload. These are local workstation measurements, excluding browser rendering and school-network/device conditions.

Investigation: the original one-process historical run missed start and report p95 at 803/943 ms. Per-student transaction locking removed advisory contention; actor-scoped reads, changed-attempt writes and three API workers brought student paths below target. A single isolated final 30-student full-year report held about 10 MB of JSON and took roughly 300 ms to load, 50 ms to reconstruct and 30 ms to serialize. Under the unchanged overlapping workload, JSON aggregation, six workers and asynchronous gzip did not bring reports below 500 ms (respective observed report p95 1,439, 1,635 and 1,174 ms in their tested topologies). The exact report body and workload were not trimmed to make the test pass. The next implementation should address the full-detail reporting read model and payload while preserving the accepted report contract, or take a proposed versioned summary/drilldown contract through the owner decision process. Any revised path must rerun the same historical workload and final counts before PERF-01 closes.
