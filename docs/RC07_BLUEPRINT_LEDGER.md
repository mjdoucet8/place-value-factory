# RC-07 blueprint ledger: 30 levels × 5 slots

Audit baseline: canonical V1 specification at `Place_Value_Factory_Codex_Handoff/Math_Factory/docs/Place_Value_Factory_V1_Product_Technical_Specification.md`, §§07–12 (20 September 2026); current config `packages/config/src/index.ts`; current generator/validator `packages/game-engine/src/index.ts`. This is an audit ledger, not a replacement product specification. **S** marks a stated specification requirement or baseline; **C** marks a current-code choice/evidence; **GAP** marks unimplemented, unproven, or conflicting behavior. Where the specification intentionally gives only a family of allowed subsets, this ledger keeps that breadth visible rather than elevating the current subset array into a product rule.

## Reading the slot ledger

Each level row supplies stage, public mode, band rule, fallback rule, and expected validation for all five slots. Each `S1…S5` cell then gives the slot's target constraint, allowed/forbidden machines, complete objective, primary skill and valid witness construction. Thus every cell inherits the row's mode/band/fallback/validator and states the slot-varying fields. Denominations are descending `[100000,10000,1000,100,10,1]`; `D` means all six machines, `D\X` means all except forbidden set X, and a vector is in that denomination order. A witness is a construction rule, not an answer exposed to a learner.

Mode/validator shorthand:

- **Canonical**: exact normal vector `floor(T/d) mod 10` at each denomination; all quantities 0–9, total and allowed machines checked. A value-correct flexible vector is acknowledged as value-correct but misses the objective.
- **Single**: only the named machine may be positive; any nonnegative whole quantity yielding T is valid (no 0–9 cap).
- **Allowed / forbidden ordinary**: any nonnegative whole vector using only allowed machines and totaling T; nonminimal equivalents ship. Forbidden is evaluated by its allowed complement.
- **Minimum**: allowed machines and exact target, plus crate count equals greedy minimum. Report value correctness separately from objective correctness.
- **Exact-k**: allowed machines and exact target, plus exactly k positive quantities (types), not k crates.
- **Two-way**: both vectors total T, obey allowed machines, and differ as full vectors.
- **Repack+minimum**: forbidden machines excluded, both source and submitted values equal T, and submitted crate count is the allowed-set minimum. Repacking is read-only source evidence, not a second objective.
- Every mode rejects malformed vectors and impossible configurations/tasks before issue; valid ordinary nonminimal representations must not be rejected. For every slot the published fallback requirement is at most 100 candidate attempts followed by a prevalidated fallback with the **same level, mode, target constraints, machines and primary skill**; if unavailable, return `CONFIG_INVALID` without issuing. **Current checkpoint:** `generateLevelOrder` tries at most 100 deterministic candidates, then uses a same-slot fallback validated for every level, slot and band when the engine loads. Signature reuse relaxes only after candidate exhaustion. The slot-specific test and integrated journey are the acceptance evidence below.

Band shorthand: stage 1 digit multipliers are easy 1–3, medium 1–6, hard 1–9. Canonical stages preserve active-position count and any zero pattern; easy digits 1–3, medium 1–6, hard 1–9. Single adjacent exchange quotient is easy 10–29, medium 30–69, hard 70–99; level 15 multi-step quotient is 100–299 / 300–699 / 700–999. Restricted tasks may narrow types/range only where the blueprint allows; otherwise preserve missing-place and objective constraints while adapting digits. Stage 6 banding must remain inside each level's target and constructive-witness constraints; it cannot remove the objective. Unknown/emerging chooses easy, developing medium, secure hard. These are S requirements; exact randomized vectors, fallbacks, and per-slot subsets absent from the source are implementation choices requiring validation.

## RC-07 implementation reconciliation (26 September 2026)

The slot table above records the specification. The current generator has 30 levels and five fixed skill-bearing slots per level. `tests/unit/rc07-blueprints.test.ts` enumerates all 150 level/slot cells across three seeds and difficulty bands, constructs independent witnesses for canonical, ordinary, exact-type and two-way objectives, checks validator acceptance, target bounds, primary attribution and Stage 2 zero patterns. `tests/unit/math.test.ts` checks greedy minimum against a separate dynamic-programming oracle over all denomination subsets and targets through 2,000. The generator validates witnesses before issue and validates its full 450-entry path fallback inventory plus place-value practice fallbacks at module load. Invalid seed/slot/objective combinations and recent-signature exhaustion are tested. Stage 1 uses all six normal-place-value machines with canonical quantities; Stage 3 uses a single machine.

`tests/integration/rc07-progression-real.test.ts` completes all 30 path levels using HTTP student commands against isolated PostgreSQL, practices every missing gate skill through saved attempts, earns all six persistent stage certifications and Factory Master, ships a nonminimal Stage 4 representation, tests an advanced objective, transfers a star once, and checks response/order/report history after a database restart. It does not seed mastery. Immutable issued specs with version, seed and slot metadata are stored in `pvf_order`; an unanswered replay order, practice schedules and certifications survive a process/database restart. Browser recovery and local pilot checks are recorded in the project status and task log.

The generator's fixed per-slot subset choices remain implementation choices under the V1 blueprint families. The milestone proves local fictional-data behavior. Physical classroom device, assistive-technology, school network and deployment approval remain later release gates.
